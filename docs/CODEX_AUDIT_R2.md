## 2. 逐条详述

### F-01：退款、升段与快照深挖

**核到的修复。** `game/main.gd:4194-4206` 在窗口结束时清来源；普通未收束站撤净、计数 `maxi(0, trade5_used - 1)`，烛台同时置 `trade1_done=false`。已完成更新①的烛台、更新②的纸扎人不退款；beat 来源另走分支，不减计数。台账“承诺拍不走让位窗口”的字面说法不准确：`:4032-4033` 实际复用 yield5_left=30、yield5_from="beat"；准确说法是它不走普通交易扣数／退款分支。

**(a) 是否能刷资源、突破交易上限？**

- 单窗口互斥成立：`game/main.gd:4019` 在窗口在途或对手空位时不开新价；每笔交易在 `:3994-4000` 加一、净站、清占位并建立一个窗口。退款清掉来源，后续 tick 不会对同一窗口反复退款（`:4194-4205`），不会把计数刷成负值。
- 没有发现由正常退款获得油、香时、更梆或额外终章交易的净收益。退款不补香；段一只有添油时升段重置香时（`:4084-4087`），油是一次性标记（`:4111-4113`），更梆一次性（`:4160-4162`）。普通开价在 `:4039-4042` 保留 `>=2` 门；段三纸扎人只做不耗次数的 beat（`:4027-4038`）。终章开局次数独立设为 1，而非从五章倒推（`:4420-4430` 的 ch6_reset_state 初始化）。
- **行为账有累计净收益**：每次交易 `:3995` 写 answer，而退款 `:4203-4205` 不撤账，`bump_behavior` 在 `:4354-4363` 把它持久加一。因此“买→烧→退款→再买”会累计两次 answer，只留下一个净交易计数；反复重试还能继续累计。不能宣称“任何资源都没有净收益”。这属于真实发生过的应答累计，与 R1 已登记的不随失败撤账口径一致；六章分支只看 drive>0 且 answer==0（`:4476`），多次 answer 不再带来额外分支收益。一次香期只有 180 秒，120 秒烧窗不支持无限循环。
- 上述正常路径的计数上限没有被退款突破；但 N-01 会产生额外的幽灵已用次数，方向是少可用次数，仍可造成死局。

**(b) “段一收束恒为1／段二快照恒可解”是否覆盖所有合法路径？**

- **在不经过问题续玩的当前一致状态中，可以证明。** 段一升段要求油齐、烛台来源窗口仍>0（`:4084`），所以升段时窗口恰恰**仍在途**，不能声称前置排除了在途窗口。安全性来自这一笔被同步消费：先 `flags.update1=true`，再 `seg5_begin(2,false)`（`:4085-4086`）；该函数先复制 trade/clean/flags 为段快照（`:3908-3909`），再清窗口（`:3915-3916`）。单窗口互斥使另一笔未退款的普通交易不能同时藏在前面。
- 段二纸扎人交易也先加一、设 update2，再同步进入段三（`:3994-4009`），新段先快照再清窗。因此在一致状态下，段二快照为1、段三为2。段二其他站的普通交易需先烧窗退款，才有机会等到纸扎人再买；时间不足可失败重试，不会正常带着额外窗口升段。
- **所有合法路径的断言仍不成立**：暂停回标题及续玩本身是合法操作，N-01 可以让段一补买前已有一个未能退款的幽灵计数，随后烛台补买变2、正常添油将2写入段二。来源校验只检查窗口，不检查计数与净的一致性（`:4084`）。

**(c) 快照／退款时序。**

- 段快照本身使用 duplicate，重试 `:4243-4250` 同步恢复计数、净表、flags，正常退款不会只改快照的一半。成功升段在退款前写快照是有意消费交易，后续窗口被清，不会再退款。
- **章存档不同**：`save_game5` 的 `data` 直接装入 clean5/flags，再 `save_data5=data`（`:4304-4306`），没有独立深拷贝；localStorage 则在 `:4308` 即时 JSON 序列化。烧窗在下次五秒自动存档前原地 erase 净、改 flags，内存存档被连带改动，整数计数及窗口秒数保持旧值。标题续玩用内存，而非重新读取 localStorage（`:4317-4348`）。这形成明确分叉。详见 N-01 的合法反例。

结论：原始连续游玩的白烧反例已修；全路径销项被 N-01 阻断。新增断言还没有读取 `seg5_snap.trade`，其“snapshot carries count 1”只检查当前计数（`game/smoke.gd:1244`）。

**其他必经与时限。** 残件、旧竹器的调查入口仍在 `:3256-3283`，不要求茶桌先净；先取得这些信息再读册，也能回茶桌补谎言。残件仍可在取档前叙述账页，修复保证的是终局前实际完成全调查，不保证所有叙述严格按时间顺序。刻意耗尽香可失败；重试清 flags/clean/squeezed（`:3067-3086`），不是不可解除的锁。本轮未发现新死局；不把局部断言当作全相位证明。本轮未实机验证。
