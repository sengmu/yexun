# 《银松镇》可借鉴设计研究——《夜巡》增量建议

研究日期：2026-11-17。范围：公开资料研究、仓内文档及源码静态抽查；本轮未运行两款游戏，未将旧冒烟、截图或他人的评测冒称亲试玩。本报告只提出方案，不授权实施，也不修改定稿。

**结论：若只做两件，先做「公平契约审计及最小补线索」，再做「可回读、可并置的实物证据」。** 前者修复玩家为什么会想到这样做，后者让已有故事成为玩家能核对的证据。主动记名可在证据系统稳定后小试；不建议全面把镇民改成谜语人。

### 仓内现状：不能把旧提案当作当前缺项

已按要求依次阅读 [DESIGN_FULL](../DESIGN_FULL.md)、[STORY_FULL](../STORY_FULL.md)、[丰富度方案](GAMEPLAY_ENRICHMENT_PLAN.md)、[R1](VERIFY_OPS_R1.md)、[R2](VERIFY_OPS_R2.md)，再读源码取证。

- 设计总纲 §4.2 已有 S-3「主线线索必达」、S-5「强制顺序要有物理因果」、S-6「一次性物件不设死局」。公平契约是将这些要求落实到每步信息来源，不另立一套相冲突的谜题原则。
- 故事本来就是「三种不正规档案」：割绳、缺页、纸轿残件/账页、长明灯、施棺簿、口述。不是缺故事素材，而是许多物证由一次性 `say()` 直接讲出结论，缺少并置观察的机会。
- 按用户给出的上线状态，命运簿、手上活、口述回访视为已有；三级提示视为在建。R1 确认命运簿是**第二章五张成功路线卡**、独立键 `yexun_ch2_routes_v1`，不是全卷证据图鉴。R2 确认木箱双域调查、工夫茶、分粿/听梆、六段实际发现后开放的口述回访；不能重新列作新功能。
- **版本边界：本地为 `main@a3c93ae`。** 当前 `game/main.gd` 没有 R1/R2 描述的命运簿接线及 `folklore.gd`；R1/R2 核验对象是 `codex/yexun-ops`，且各自注明当时网页仍为 YX-11。因此下面源码抽查只证明本地流程；后续修订以交付核验补注，不能从本地旧代码断言线上回归。用户「全卷已上线」为本轮产品前提，本报告不另行联网核验《夜巡》部署版本。
- 总纲中仍有早期「仅一章上线」「SP 待确认」等历史措辞；以本轮用户明确的六章定版、SP 已锁定、结局固定为准。R2 已有小模块也不构成本轮允许重构的依据；新建议按 `main.gd` 内的少量表/函数与既有入口估工，不要求拆架构。

## ② 逐候选裁决

工时均为未来实施的粗估：一名熟悉项目的开发者，含文案整理、局部功能和键鼠/触屏回归，不含等待过稿、全卷真人验收及现有分支整合。1 人日按 8 小时计。资源数字是**增量预算上限建议**，并非已导出的测量值；每项都须看 PCK/首载实际差值与字体子集差值。

### 候选 1：碎片文件叙事——条件推荐，缩为「实物证据回读与互证」

**银松镇怎么做。** 见 S2 的文书叙事观察；相机笔记的直接用途由 S3 支持。可借的是保留证据原貌和来源，让玩家回头对照；现有资料不足以断言其有某种完整证据连线判题系统。

**夜巡现状。** 第一章花灯已照割口，第二章花灯/水缸可调查，第三章名册连续翻两次、残件触发账页、竹器触发记忆。`act3()` 把 `remains_seen` 与 `account_found` 同时置真，玩家并没有亲手做两个来源的核对。R2 的口述回访解决六段口述回读，不等于涵盖物证。六章补页是活人的公开认错，不能被档案玩法取代。

**具体借法。** 首版只做六张来源卡：一章割痕、一章落签、二章招牌割痕、三章今晚换绳栏、三章旧档撕口、三章牌位布与支出账页（同卡分两面）。必须实际触发才登记，保留章/地点/物件/原文；摘要不得提前说破「六叔公授意」或私签来历。

在原物件处「留下一份观察」而非把物件从场景拿走：亡魂不能随身搬走名册、破坏绳索或持有新背包。打开卡面可回读；选择两张已发现的卡并置，例如两处割口的相同切面、残字与账页的名字。初版只让玩家选择和观察，**不设答对门槛、不自动宣布案件结论**。旧档被撕掉的页本来不在现场，不可新增一张恰好写全真相的「可拾取撕页」；应记录现存撕口与漏网账页。

签文只收录已公开的「逢冲则避」；第五章后才追加其来源；最后一附仍只记「已回收」，永不补写定稿故意不公开的全文。四章记忆只在触发后开放；不能凭三章通关提前解锁。记录在回香后可保留，不能把卡的已读状态回灌到本局通关旗标。

**改动面与工时。** 原调查成功位置加稳定 ID、一个共用回读页与双卡并置、独立记录/坏数据回退；优先复用现有回访入口，命运簿保留成功路线语义。约 **4–6 人日**；若只做纯文本回读约 2–3 人日，但互证价值较弱。程序排字和既有精灵裁切为主，新增代码/文本预算 ≤100 KiB，零新音轨、零整屏美术；如坚持 6 张 512×512 纸面纹理，合计预算 ≤0.6 MiB，必须单独算导入后体积，否则不做。

**冲突检查与边界。** 零战斗、无惩罚、六章和解不变；不删改现有台词、不把可选阅读变主线安全门。新增卡面文字/观察须过稿。「互证成功后才准通关」「删除原揭晓对白，改为全靠文件」「新增真实可拾取的缺页」均不推荐；前两项属**「提案改动定稿」：需用户另行批准**，第三项还冲突既定失证事实。本轮不将它们列为执行方案。

**裁决理由。** 主题适配度高，但完整碎片叙事重制会动定稿、重复既有回访并扩大包体；上述小范围方案才成立。验收看玩家能否指出两件证据如何互证，而非收满卡数。

### 候选 2：「线索一定在场景里」——推荐，作为逐步审计契约

**银松镇怎么做。** S2 将答案有场景/文件来源视为优点，这是评价，不是开发者对全游戏的形式保证。S5 的个案说明「信息存在」与「玩家理解操作」仍有距离。

**夜巡现状。** 多章常驻目标及 H 已给到物件和按键；这满足游戏内可查答案的弱条件，却不能证明玩家能推理。第一章「燎金纸→庙祝移炮」最明显：`objective_text()` 与 `hint_text()` 事前直接给答案，`act()` 烛台成功后才交代动作结果；并没有足以支撑这串特定因果的场景铺垫。用户提供的真人试玩实证与此静态观察一致。

**具体借法。** 每一处必经推理/强制顺序写六项账：玩家目标、所需事实、事前信息载体/出现阶段、合法推导、备选路径、失败后如何重获信息。区分四类文本：场景证据、操作前教学、主动提示、操作后结果。后两者不能独自替代前两者。线索可以在同章其他物件或已读卡里，不要求紧贴答案；不可要求玩家已有潮汕民俗知识。

第一章最小补法是**新增事前可读观察**：让玩家看见金纸火可能燎及鞭炮、庙祝正在兼顾火与鞭炮，且架脚石礅是已有的避火放置处。只加「火能引人」仍解释不了他为何摘炮、为何放到那里。这些观察须过稿并确认画面确实支持，不能先写成现实中不存在的摆设。所有原成功/失败台词原样保留。若需要改变既有摆设或剧情调度才说得通，应另列**「提案改动定稿」：需用户另行批准**，不能伪装为提示优化。

三级 H 在建时同步对账：首层只指可疑处，次层提示关联，末层给原操作；但**保留现有常驻目标和定稿 H**，本报告不自行将其降调或重写。要把常驻解法改成低剧透目标，属于改变现行文案，须另行审批。公平审计先补缺因果，不以增加 H 次数掩盖缺证据。

**改动面与工时。** 完整六章逐步台账与过稿补线索包约 **2–3 人日**；按本轮高风险点做最小新增观察再加 **2–4 人日**，合计 4–7 人日。无新系统、无新增必达旗标；新增 UTF-8 观察/提示表预算 ≤50 KiB，字体增字重算，优先程序高亮既有部位而非新图。

**冲突检查。** 只审核和补充信息不触及战斗、失败、章数、结局、SP 或架构；不能新增扣香、强制失败教学、证据答题门。安全前置不能为「更公平」而绕过。可选口述依然只是加料，不能升为通关必读。

**裁决理由。** 这是收益最确定的一项：先让现有解法说得通，再谈更多内容。表③为抽样起点，不能冒称已审完所有分支或已通过真人验收。

### 候选 3：镇民只说一半——条件推荐少量新增，不推荐全面谜语化

**银松镇怎么做。** 可疑镇民由官方列为特征，保留与答非所问的具体气质来自 S2；并无可核读的全部 NPC 台词，不能逐句仿写。

**夜巡现状。** 庙祝「绳是新换的」本来就是知情而退缩；管册人「我爹那辈的事」推开责任；六叔公以茶压场，「食茶，慢慢查」是体面的回避。第四章对玩家揭死因、庙祝讲引路轿旧规；第五章庙祝说全自己的沉默，水生交绳，公开真相；第六章认错补页。这些已经比统一的神秘语气更有人物动机。

**具体借法。** 如确需加强，仅在一至三章可选调查里新增极短的「可见反应＋实物指向」：庙祝回避谈验绳却持续看供桌边的绳头；六叔公回避旧档年份却把茶推到册柜前。此处是**演出方向提案，非获批台词或已存在事实**；新增物件/手势须确认不改历史动作、不把活人写成能听到亡魂发问。以小英等活人的询问、旁听或物件动作触发，不能直接做阿澄与镇民问答树。

每一条扣子写清回收点：庙祝的扣在五章「没敢再说」，六叔公的扣在六章补页。前几章只留事实的边缘，不能新增明确主谋指认；四章以后不再对已揭事实故作神秘。规则性信息（如何示警、如何应答）必须清楚，隐瞒只服务动机与责任。

**改动面与工时。** 至多两处可选旁听、各一条新反应及来源标记，约 **1.5–3 人日**；零新立绘、零配音，文字预算 ≤10 KiB。若加多分支问答、全卷重写语气或新表情动画，不列入本案。

**冲突检查。** 新增内容也须逐字过稿；不改一字定稿、不挪既有揭晓时点、不改变谁知情。将「绳是新换的」替换成更隐晦的句子、拆改第五章全句、提前在一二章让六叔公正面认领责任，均属**「提案改动定稿」：需用户另行批准**，且本报告不推荐。新增旁听仍须克制对白总量，不挤占原人物爆点。

**裁决理由。** 当前主要缺可核对证据，不缺半句话。只有用户觉得特定人物尚缺回避的可见行为时才值得补，不应作为本轮优先项。

### 候选 4：相机标记→主动「记名」——条件推荐，做可撤销的私人书签

**银松镇怎么做。** S3 开发者说明的是记忆辅助；S4 的扩容和快捷菜单选项表明，它既有价值也可能妨碍操作。没有可靠依据把照片解释为结局考核。

**夜巡现状。** 命运簿在成功后自动存第二章路线；R2 回访按实际发现留档。二者记录「系统认定发生过什么」，尚未提供「玩家现在觉得什么值得追查」的动作。但《夜巡》章节更短、附身图更小，照搬地图拍照收益有限。

**具体借法。** 在候选 1 的来源卡上加一个可选「记一笔」：玩家选择一条已读事实，标为「待对照」或自行取消；可选另一张卡并置。比如把「水生经手」与「库房灯亮过」放在一起。只存证据 ID 和书签状态，不替玩家写「凶手就是……」。可先在三章试两组线索，观察是否真被用于回看；若只是多点一次，删除这个增量。

视觉可以是记忆页边一笔墨痕；明确它属于玩家的私人整理，不是阿澄在现实名册上改字。**不让玩家代替六叔公补名册**，也不把自己输入的人名投射到终章。无自由输入首版：Web 手机输入法、审阅范围与存储负担都不值得；也不用截图/照片文件。未记名依然完整通关、看到同一和解结局，无倒计时书写或书错惩罚。

**改动面与工时。** 候选 1 之后增量 **1–2 人日**；独立建设入口/回读/持久化约 3–4 人日，性价比下降。`main.gd` 内一组独立元记录，沿既有回访 UI 模式接入，不能写入行为账、`pre_all` 或章快照。≤30 KiB 代码/文本，无新贴图，满量已读/标记 JSON 预算 ≤10 KiB；损坏或禁用存储时退为会话书签。

**冲突检查。** 自动记录仍保留；回香不擦掉玩家书签，也不恢复本局谜题进度。改变现实名册、改六章补页角色，或以书签完整度决定结局，直接不推荐；前者属**「提案改动定稿」：需用户另行批准**，后者还违反固定结局与不惩罚。新增「记一笔」标签和说明须过稿。

**裁决理由。** 可以强化「认一个被漏掉的人」的主题，但必须先有值得比较的证据；不值得为这个主题另起背包、地图、手写识别和收藏考核系统。

### 新发现 5：旧工具用途的再理解——条件推荐，只补回看比较

**银松镇怎么做。** S1 的探索结构和 S3 玩家用工具处理旧障碍，带来「原来那里还能这样用」的回访；不等于《夜巡》应新增武器或多层地图。

**夜巡现状。** 已有更贴合主题的同物多义：响器由二三章驱赶变四章应答、五章开价、六章报到；纸扎物从怪异变雷达；花灯从照割痕变照路。机制升级基本做完，无需为了借鉴再建同类系统。

**具体借法。** 仅当相关原事件都已触发，允许在既有回读页并置「同一物件当时做了什么」的来源片段；用两次动作结果供玩家比较，不新增旁白解释。五章前不能看到六章报到，不用后章知识自动解锁前章未发现项。若现有回访已经达到同样效果，则本项不再开发。

**改动面与工时。** 依候选 1 增加 2–3 组来源关联，**0.5–1.5 人日**；≤20 KiB 文本/表，不加演出资源。不要新建跨章自由回游或重复解锁。

**冲突检查。** 原机制、台词和揭晓不动，无战斗/惩罚；只引用已触发原文。新解释文案须过稿。把响器增加第五种必经用途、强迫回旧章取道具，会扩大六章流程与安全判定，不推荐。

**裁决理由。** 可强化玩家对纸灶态度的变化，但新增收益小于证据与公平修补；先确认既有功能是否已足够。

### 新发现 6：让「可见线索」也「可辨识、可重获」——推荐小范围落实

**银松镇怎么做。** S4 提供正式版字号、存储与软锁修复的直接证据；S5 半破箱个案提示中间态未必被理解。这里借的是负面经验：不能只证明某张线索曾显示过。

**夜巡现状。** 物件技能名、青/红灵核、头朝向、环纹、雾锢和提示共同传递信息；三级 H 在建，R2 回访已有白名单恢复，但报告同时披露原生持久化缺口。本地的多段大段 `say()` 易被下一次动作覆盖，能否在手机上看清环纹和原文不由静态源码证明。

**具体借法。** 首先验现有新功能：键鼠/触屏下确认「尚未观察／已观察／待比较」可区分，关键状态同时有图形和短文字，不只靠红青颜色或声响。证据页打开时仿照 R2 可选练习冻结主线计时，关闭后恢复；不要求在限时里翻长文。已读 ID 可跨回香保留，本局功能旗标严格隔离；刷新、损坏存储、旧记录及会话模式下至少能再次打开来源。原生跨进程存储另作发行事项，不将本报告扩大为云存档改造。

**改动面与工时。** 依实际验收只修高风险项，**1–2 人日**；复用字体/绘制/已有暂停入口，≤30 KiB 代码与短标签，零新音轨。字体增字单计。不另起设置系统或重构 UI 框架。

**冲突检查。** 新辅助不扣时、不取消原回香、不改变谜题前置；不改 SP 色调，符号/文字只作辅助。不能为「状态清楚」把隐藏真相提前写在未读条目上；界面文案仍须过稿。与所有硬约束相容。

**裁决理由。** 这是候选 1/4 有用的前提，宜作为它们的小范围验收工作合做，避免报告提出一套玩家实际读不到的证据系统。

## ③ 公平契约抽查结果表

### 判定方法

以下检查的是**信息公平**，不是通关条件是否存在。A＝操作前已有可读来源或明确教学，能支持这一步；B＝游戏内目标/H/无代价试探能带过去，但事前因果或指向偏弱；C＝特定必要动作缺足够事前来源，或来源/提示漏掉真实必要条件。B/C 都须登记改进，不能用「H 里写了」宣称自然推理已通过。谜底身份可以延迟揭晓，操作所需事实不能靠未来章节补课。

主要取证链接指当前检出版本，代码将来移动时以函数与分支名重定位。表内「事后」不计作首轮事前证据；凡仅为源码与文字判断，视觉可读性仍待真人验证。用户给出的第一章试玩结论是**用户提供的实证**，不是本轮亲测。

### 抽查后的处置优先级

1. **先处理两个 C：** 第一章移炮的事前因果、第三章取谎的必要线索指向。前者有用户试玩实证；后者为本地代码发现，须在实际交付版本先复核，若新提示已覆盖则结案，不能重复修。

4. **下一轮真人验收取证：** 在真实当前包各走一次不按 H 的观察路线与一次主动求助路线；记录玩家操作前能否说出因果、引用哪件物证，以及回香后能否再次找到。程序冒烟只能验证状态，不代替「我为什么想到这样做」的证据。
