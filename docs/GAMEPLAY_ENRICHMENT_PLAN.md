基线：远端 `main@914fccf`，核对 [DESIGN_FULL.md](../DESIGN_FULL.md) §3.2、§4.1–4.3、§6、§8，以及 [Godot 源码](../game/main.gd)。以下是逐分支静态审计和施工提案，未运行游戏，未把已有台账中的冒烟或分镜截图当作本轮试玩证据。

## 逐章差距审计

**计数口径。** 分母是章节物件节点，六章按分段合并去重。分子分两层：「有反馈」指有专属操作或附身反馈；「有规则用途」指该物件在常规流程或可达分支中能改变导航、时间、对手、角色调度或通关前置。一次性教程、只写入已读标志、仅改变台词/H 文案、声光动效和共用附身移动均不计入第二层。可靠但未被程序强制使用的雷达单独记入观察。六章的签由灵域特判处理，因此纳入两层。三至五章的响器一件只计一次，无论用于驱赶还是应答。

**取证入口。** 一章：`nodes`、`act`、`finish` 与 `objective_text/hint_text`。二章：`CH2_NODES`、`jump_to`、`act2/act_sound2`、`try_scare`、`objective_text2/hint_text2`。三章：`CH3_NODES`、`jump_to`、`scare3`、`act3` 的 `pre_all`、`objective_text3/hint_text3`。四章：`CH4_NODES`、`jump_to`、`bm_maybe_enter/bm_answer`、`act4`、`objective_text4/hint_text4`。五章：`CH5_NODES`、`seg5_begin/trade5_do`、`act5`、`objective_text5/hint_text5`。六章：`CH6_NODES/ch6_graph_for`、`jump_to` 的签分支、`seg6_begin`、`act6/trio_hit6`、`finish6/enter_epilogue`、`objective_text6/hint_text6`。节点和分支以同一远端提交读取。

**横向结论。** 六章都有真正的双域操作，新增物件价值集中在「现实动作前必须看懂灵域信息」和「读完能回看」。现有分层是常驻目标、条件反馈、手动 H、失败提示，H 对同一状态只返回一条，没有逐次加深。总纲 §4.1 要求按进度指向、不给完整解法，与多章 H 明示具体操作有差距。另有标题选章和尾声回看，未发现独立计时模式、跨章线索图鉴或隐藏对白收集。

**终章重玩限制。** `start_incense6` 从 Web 行为账取快照，西巷入段要求 `drive > 0 && answer == 0` 才进入驱散变体。四章必经借嘴和五章必经交易均记 `answer`，因此正常连续 Web 通关不宜承诺能解锁驱散变体；独立选章或不同行为账可能表现不同，需浏览器验证。此方案保留现行规则，不把驱散设为收集完成门槛。A2、P-06 等原有待决项另行拍板。

## 前三项施工细案

### 1. 三级手动提示

- **入口。** 保留常驻目标、失败台词、教程与原有快捷键；H 与触碰提示入口共用提示层。第一次请求只描述卡点，第二次说明因果或替代项，第三次复用当前 `hint_text*()` 原文。当前状态没配新提示时沿用原 H，避免提示消失。
- **阶段键。** 用章、段和关键前置计算稳定键。相同目标反复请求才升级；换段、回香重试、回标题或目标确实变化时回到第一层。倒计时每帧变化不参与键。单次点击只升一层；不在失败和教程加门槛。
- **样例。** 三章缺查册窗口时，第一层提示柜前还站着人，第二层指茶盖或香案皆可支开管事，第三层复用现有操作提示。五章先区分普通占位与静候，再解释为什么此刻响器只能驱赶或能够开价。六章门环先指出应让门口看清，第二层指花灯，第三层给出已有顺序。
- **验收。** 每章走一个真实卡点连按三次，核对提示递进；在正确推进、失败回香、同章刷新后验证复位。三章两条取档路线、五章耗尽窗口、六章未入巷或未照门分别验证。核对固定对白逐字一致，桌面与手机上均能读完。

### 2. 可回看线索簿

- **首版范围。** 一章落签和花灯割痕；三章今夜排班册、撕掉的旧档页、旧竹器记忆；四章花灯担记忆；六章最后一附只记「已回收」，保留签面全文未公开的定稿。按原触发成功才加一条，条目稳定 ID 去重；不从临时对白全文里解析状态。
- **入口与留存。** 标题页进入线索簿，按章节显示已读条目和已知来源。未见条目隐藏标题与摘要；正文引用原文或用经审阅的非剧透摘要，完整记忆仅在实际触发后可见。记录放在单独的带版本号的键，存已见 ID，不把字典挂到章存档，不读取或写入行为账；无存储能力时可在当前会话回看。
- **重试边界。** 回香可保留玩家已读信息，绝不把图鉴解锁回灌为玩法旗标。旧档开启仍可按原路获得，首版不从全卷通关标记推断玩家见过每条线索。
- **验收。** 对每条执行触发、重试、回标题、刷新和重复触发，核对只登记一次；另测空存储、旧存档和损坏值，确认菜单可打开且没有剧透。比对通关前置和行为账值未变。

### 3. 三章旧木箱双域可选调查

- **入口与顺序。** 开档后，玩家在现实操作旧木箱，先完整显示既有封存清单对白。此后灵域可从邻接节点看到箱沿新增的低饱和纹样重合提示，可用一个不夺取主要输入的短观察动作记录。回到现实再查，才追加一条图鉴可选记录，内容只补「箱沿压痕与封存纸条位置」的观察，不新增证人、失窃或案件结论。
- **状态边界。** 只用独立可选调查状态记录「原清单可读／已看灵域纹／已回查」；不向 `pre_all`、支开守册人的窗口、香时或模仿计数添加条件。保持原图和跳跃计数，不要求额外跳跃；可以在标准走位观察，误操作无新增扣时。状态未完成时可离开，回香后可重新做；如第 2 项获批，已记录条目按线索簿规则保留。
- **画面与输入。** 复用木箱、后殿与原灵域色调，纹样用小范围 SP 风格叠层；不加惊跳、突然近景或新声音峰值。独立观察入口只在有效位置出现；灵域依然不能推动实体，现实中的活人不看见纹样。
- **验收。** 主线不碰木箱、只读原清单、看完纹样再回查各走一次，三条都可按原六项证据收束。验证窗口未开／已关、对手占位、回香、重复调查、键鼠与触屏。原清单台词保持原样，新增提示和记录经审阅后再实现。

## 开工条件与不变量

只新增内容。保持所有定稿台词、剧情、SP 低饱和手绘水彩、零跳吓及失败回香重试。新增可选条目遵守 S-1 至 S-10，尤其不得把可选线索变必经、偷改安全前置或占位规则。各案如触及支线判定、A2、拍板清单或发行决定，留待用户另裁；任务五、六、七暂停。

仅在用户选定条目且另一台机器的 N-01 修复已推送后开工。开工前从远端 pull 最新 `main`，确认 N-01 的提交和对应回归已进入基线。先记录修复后的基准冒烟结果，之后每项独立交付，附真实路径验证与回滚边界。
